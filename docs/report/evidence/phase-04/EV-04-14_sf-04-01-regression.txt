EV-04-14: Security finding SF-04-01, regression test before and after the fix
Captured: 2026-10-05 (UTC) on branch feature/CM-T023-cryptographic-vault (Phase 4, uncommitted working tree)
Finding: the prerendered /login and /register forms declared no method. Submitted before the client bundle had run,
the browser sent a native GET with every field in the URL. Severity High (account password in URLs, server logs and
browser history). Introduced in Phase 3, found and fixed in Phase 4. Record: docs/management/phase-04-traceability.md section 4.
Redaction: the probe used the synthetic canary value <canary> (no account was created).

1. Reproduction on the unfixed build (scratch probe: client scripts blocked, fields filled, submit clicked):
   /register -> GET /register?email=probe%40example.test&displayName=&password=<canary>&confirm=
   /login    -> GET /login?email=probe%40example.test&password=<canary>

2. The new regression test on the unfixed build (Chromium) FAILS:

     1) [chromium] › tests\e2e\web-shell.spec.ts:74:3 › /login: a form submitted before the client runs sends no typed value anywhere 
       Error: expect(locator).toBeDisabled() failed

     2) [chromium] › tests\e2e\web-shell.spec.ts:74:3 › /register: a form submitted before the client runs sends no typed value anywhere

     2 failed

3. Fix: CSP form-action 'none' (apps/web/scripts/csp-lib.mjs) and buttons disabled until hydration
   (apps/web/src/components/ui.tsx). Generated header after the rebuild: form-action 'none'.
   Prerendered button: <button type="submit" disabled="" ...>
